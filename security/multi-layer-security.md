# 多层安全防护体系

> AI 操作主机的安全不能靠单一防线，需要从外到内层层兜底。

## 五层防护

```
1. 插件市场预检   ← 下载前静态扫描，高危直接拒绝安装
2. 本地 AI 审查   ← 语义层识别隐藏意图、混淆代码（3B 模型）
3. 恶意检测器     ← 命令黑名单 / 路径黑名单 / 行为异常
4. DLP 防泄密     ← 域名白名单 / 敏感内容 / 剪贴板拦截
5. 沙箱资源隔离   ← seatbelt + 10GB 配额，进程级隔离
```

## 每层的定位

| 层 | 能拦什么 | 拦不住什么 |
|---|---|---|
| 插件市场 | 明显恶意代码、黑名单依赖 | 加密混淆、远程加载的后门 |
| AI 审查 | 迂回话术、隐藏意图、prompt 注入 | 小模型能力有限的复杂混淆 |
| 恶意检测 | 高危命令、敏感路径、fork 炸弹 | 动态拼接绕过关键词的代码 |
| DLP | 域名外发、密钥泄露、剪贴板读取 | base64/隐写/分片小请求 |
| 沙箱 | 逃逸后的破坏范围（受限） | 沙箱本身的漏洞（无 100% 安全） |

## 关键原则

1. **沙箱不是安全边界，只是降低风险**（官方文档原话）
2. **AI 审查不能替代规则检测**，规则永远兜底
3. **不要给沙箱内进程辅助功能权限**——一旦给了，沙箱隔离作废
4. **full-access 只做人工审批的一次性会话**，用完销毁，且 DLP 持续生效
5. 生产环境叠加 gVisor / microVM

## 权限升级设计（人工审批）

```
AI 请求完全权限
  → 插件拦截（沙箱内无权触发）
  → 弹窗人工确认
  → 创建一次性 full-access 会话（绕过 seatbelt，但 DLP 仍在）
  → 用完销毁
```
