# DLP 防泄密

> Data Loss Prevention：防止沙箱内 AI/插件把敏感数据偷偷外发。

## 核心思路

```
沙箱内代码
  → 出站请求 / 文件读取 / 剪贴板读取
  → DLP 拦截器
    ├─ 命中敏感内容 → 阻断 + 审计告警
    └─ 非敏感 + 白名单域名 → 放行
```

## 三道检查

### 1. 出站请求

- **域名白名单**：默认只放行 `api.deepseek.com`
- **内容扫描**：请求体匹配敏感正则直接阻断

### 2. 文件读取

- **敏感路径拦截**：`~/.ssh`、`~/.aws`、`~/.config` 等
- **内容匹配**：读到的文件含 API Key / 私钥 / 身份证号 → 阻断

### 3. 剪贴板

- 默认禁止 AI 读取剪贴板（对接 GUI 代理时生效）

## 敏感内容正则示例

```ts
/ sk-[a-zA-Z0-9]{20,} /                                // DeepSeek API Key
/ -----BEGIN (RSA |EC )?PRIVATE KEY----- /              // 私钥 PEM
/ password\s*[:=]\s*["'][^"']+["'] /i                   // 密码
/ \b\d{17}[\dXx]\b /                                    // 身份证号
```

## 关键设计

- **full-access 会话 DLP 也持续生效**：人工审批拿到全权限后，依然防外传
- **密钥不进沙箱环境变量**：DLP 是兜底，不是唯一防线
- **沙箱网络强制走本地 DLP 代理**：seatbelt 底层只放行本地代理端口

## 已知局限（要清楚）

| 绕过方式 | 是否已防 | 说明 |
|---|---|---|
| base64 / URL 编码 | ❌ | 需解码后二次检测（后续迭代） |
| 分片小请求 | ❌ | 需聚合分析（后续迭代） |
| 图片隐写 | ❌ | 高级对抗，暂不处理 |
| 大文件打包上传 | ❌ | 需检测 tar/zip 批量上传 |

## 日志
